# Агрегатор: новости из внешних источников

Живой документ: правится по мере реализации. Имена ролей и клиентов — в [auth.md](auth.md), источник правды для них там. Топология — `model_v2.c4`, вид `parsingFlow`. Подробно расписана часть 1, остальные — тем, что решено и что открыто.

## 1. Термины

- **Источник** — одна лента одного сайта. eurosport.fr и tntsports.co.uk — разные источники.
- **Профиль** — настройки источника: откуда и как забирать, что брать, как часто, как вести себя на сайте.
- **Ступень** — способ забрать ленту: RSS, news-sitemap или HTML-страница ленты.
- **Новость** — одна статья источника. Одна статья — одна запись, сколько бы раз её ни видели.
- **Сюжет** — новости разных источников об одном событии (§5.3).

## 2. Части

| Часть | Что | Статус |
|---|---|---|
| 1. Сбор | `parsing-service`: открытые сайты — RSS, news-sitemap, HTML | §4 |
| 2. Хранение | `aggregator-service`: одна статья — одна запись, приём от сборщика | §5.1 |
| 3. Редакция | лента в «Источниках», «Новый материал по новости» | §5.2 |
| 4. Сюжеты | склейка похожих новостей | §5.3, после замера |
| 5. Закрытые сайты | сайты за антибот-защитой | §5.4 |
| 6. Соцсети | Instagram, Twitter: посты, сторис, ответы | §5.5 |

## 3. Решения

- **Два сервиса.** `parsing-service` (Python) собирает, `aggregator-service` (Java) хранит и отдаёт редакции. Разрез — по тому, что меняется: сборщики ломаются и переписываются постоянно (сайты, защиты, соцсети, сторонние скраперы), а данные и API редакции стабильны. Сборщик можно переписать, заменить сторонним или выключить — редакция этого не заметит.
- **Что брать с источника, решает его профиль**, а не общий код.
- **Одна статья — одна запись** (канонический URL, id из ленты). Похожие новости разных источников не выбрасываются и не сливаются: связываются в сюжет (§5.3).
- **Собирается только новое** с момента запуска. Архив сайтов не выкачивается.
- **LLM не используется.** Решение — после замера на реальных данных (§5.3).

## 4. Часть 1: сборщик `parsing-service`

Полноценный сбор начнётся вместе с запуском всего сервиса. До агрегатора сборщик запускается локально, для проверки источников, и пишет в файлы (§4.9).

### 4.1 Источники

Стартовые. Проверены 04–06.10.2026 честным User-Agent (§4.7).

|---|---|---|---|---|
| Eurosport / TNT Sports | EN (tntsports.co.uk), FR, DE, IT, ES, NL | news-sitemap `/sitemaps/news/sitemap-news-recent.xml` | 1 мин | шесть источников, одна платформа. В sitemap все виды спорта за 48 часов: фильтр по разделу (`/tennis/`, в испанской `/tenis/`), видео (`_vid`) отбрасывается. Текст — только тело статьи (`[data-testid="body"]`) без промо; подзаголовок остаётся в лиде, обрезанный до 160 символов. Польская версия устроена иначе |

Цель для новостей — появиться у нас за 1–2 минуты. Быстрее самого источника не выйдет: если сайт обновляет sitemap раз в несколько минут, новость придёт с этой задержкой. Реальную задержку показывает разница «опубликовано» и «увидели» (§4.4).

Проверены по §4.3 06.10.2026 на 10 статьях: Tennis Majors и Bounces — общего извлечения хватает; Eurosport — с селекторами в профиле, одними на шесть версий. sports.ru (07.10) — с селекторами тела новости; статьи — общим извлечением. На всей странице Eurosport общее извлечение захватывает подпись автора, кнопку «на Google», превью видео, карточки «читайте также» и промо в конце, а заголовок и подзаголовок то оставляет, то теряет.

Не взят: ESPN. RSS, API и sitemap отвечают честному боту заглушкой защиты (202 с пустым телом, 403). Часть 5.

### 4.2 Профиль

Файл `sources.yaml` в `parsing-service`. В части 2 он станет начальным наполнением реестра источников в агрегаторе.

| Поле | Что |
|---|---|
| `key` | id источника: `eurosport-fr`, `sports-ru` |
| `name` | название для людей |
| `kind` | `rss`, `news_sitemap`, `html` |
| `url` | адрес ленты |
| `hosts` | хосты, с которых разрешено качать страницы (§4.8) |
| `language` | язык источника. Определения по тексту нет: источники одноязычные |
| `content_mode` | `full` — качать страницу и извлекать текст; `lead` — только то, что дала лента |
| `include`, `exclude` | шаблоны URL: какие записи брать |
| `interval` | как часто опрашивать |
| `quiet_after` | сколько источник может молчать без тревоги (§4.11); по умолчанию сутки, у Bounces — 10 дней |
| `respect_robots` | соблюдать ли robots.txt (§4.7) |
| `extract` | необязательно, если общее извлечение не справилось (§4.3): `body` — CSS-селектор тела статьи, `drop` — что из него выкинуть, `drop_paragraphs` — регулярки для абзацев (селектор абзаца — `paragraph`), которые выкидываются по тексту: промо и «читайте также», вписанные в тело обычными абзацами; `published` — элемент с атрибутом `datetime`, точное время публикации, когда его нет в ленте. Без правила время ищется в `article:published_time` |
| `listing` | только для `html`: `item` — одна запись списка, `link` — ссылка на статью в ней, `title` — заголовок (иначе текст ссылки), `lead_attr` — атрибут ссылки с лидом. Без `item` записью считается каждая подходящая ссылка; карточка часто ссылается дважды (картинка, заголовок, комментарии) — склеивается по каноническому URL, побеждает самый длинный текст. Пустой список — ошибка прогона: селекторы перестали подходить |
| `enabled` | |

### 4.3 Подключение источника

1. Ступень: есть ли RSS; если нет — news-sitemap (`Sitemap:` в robots.txt); если нет — HTML-страница ленты. Закрытые защитой — часть 5.
2. robots.txt: что из нужного запрещено. Решение — флаг `respect_robots`.
3. Прогон `run-once` (§4.6) и сравнение извлечённого с оригиналом на ~10 статьях: текст целиком, без подписей к фото, рекламы и «читайте также», цитаты на месте.
4. Где плохо — правила в `extract`.
5. Если в `extract` появились правила — одна страница источника в тесты, без скриптов и атрибутов `class`: тест держит правила на настоящей разметке. Редизайн сайта такой тест не поймает, его видно по сбоям извлечения в отчётах прогонов.

### 4.4 Что берётся с новости

| Поле | Откуда |
|---|---|
| Источник, язык | профиль |
| Заголовок | лента |
| Ссылка (канонический URL) и id | лента; со страницы — `rel=canonical`, `og:url` |
| Дата публикации | лента, уточняется со страницы |
| Когда увидели | сборщик |
| Лид | RSS; для sitemap и HTML — `og:description` страницы |
| Текст | страница статьи, по `content_mode` |
| Автор | лента или страница |
| Главная картинка | страница, только ссылка: обложкой она не станет (`FOREIGN_MEDIA`, [editorial.md](editorial.md) §5), это превью для ленты |
| Рубрики и теги | лента или страница |
| Встроенные посты | ссылки на X/Twitter, Instagram, YouTube из статьи. Сами посты не качаются |
| Статус извлечения | `ok`, `failed` (остался лид), `skipped` (`lead`) |

- Текст — markdown: абзацы, подзаголовки, цитаты, списки. Цитаты игроков — основное сырьё, и в панели редактора, и в AI-чате со структурой удобнее.
- Извлечение общее — trafilatura: находит тело статьи без настройки под сайт и переводит разметку в markdown. Селекторы — только там, где оно ошиблось (§4.3). По всей странице trafilatura осторожна (`favor_precision`), чтобы не захватить меню и анонсы; в теле, выбранном профилем, короткие абзацы не выкидываются — иначе пропадают строки сводок результатов.
- Кодировка страницы: из ответа, иначе `<meta charset>`, иначе UTF-8.
- Исходный HTML страницы хранится сжатым рядом с результатом: видно, где извлечение ошиблось, и после правки селекторов страница разбирается заново без запроса к сайту. Что с ним делать после части 1 — §5.1.
- Изменения уже виденной статьи — новая дата или заголовок в ленте — записываются, статья заново не качается. Перечитывать ли — решение по данным: как часто это бывает и у каких источников.
- Страница, не отдавшаяся из-за временной ошибки, спрашивается снова. При проверке Eurosport Italia семь страниц из sitemap минут на десять отдавали 404 и потом открылись; без повтора эти новости остались бы без текста навсегда.
    - Временная ошибка — 404, 408, 425, 5xx, таймаут, обрыв соединения. Постоянная — 410 и прочие коды, редирект на чужой хост, слишком большой ответ, страница без текста, сбой извлечения: такие не повторяются.
    - Новость записывается сразу, с лидом и статусом `failed`: редакция видит её без задержки. Страница встаёт в очередь повтора и спрашивается через 5 минут, 15 минут, час и 3 часа; после четвёртой неудачи — всё.
    - Удачный повтор записывает новость ещё раз, с тем же URL и `first_seen_at`, уже с текстом. Агрегатор примет её как обновление записи (§5.1).
    - Очередь не зависит от ленты: статья, ушедшая из RSS или sitemap, всё равно будет спрошена.

### 4.5 Прогон источника

1. Условный GET ленты: `If-None-Match`, `If-Modified-Since`. 304 — прогон окончен.
2. Адаптер ступени отдаёт записи: RSS — feedparser, news-sitemap — XML, HTML — селекторы `listing`.
3. Канонический URL: без `utm_*`, `at_*`, `fbclid`, `gclid` и фрагмента.
4. Фильтры `include` и `exclude`. Виденные пропускаются, изменения у них записываются (§4.4).
5. `full`: страница статьи — trafilatura, метаданные, встройки. Сбой — новость остаётся с лидом и статусом `failed`.
6. Запись результата (§4.9), после неё URL отмечается виденным. Упадёт запись — новость возьмётся следующим прогоном.
7. Повторы, у которых подошёл срок, — не больше 20 за прогон, по тем же правилам: robots.txt, одна страница сайта в секунду, блокировка останавливает прогон (§4.4). Идут и тогда, когда лента ответила 304.
8. Отчёт о прогоне: HTTP-код ленты, записей, новых, сбоев извлечения, повторов и удачных повторов, блокировка, ошибка.

### 4.6 Расписание и состояние

- arq-воркер. Cron раз в минуту ставит задачи источникам, у которых подошёл срок. Одна задача на источник (`_job_id = fetch:<key>`), прогоны одного источника не накладываются, у задачи таймаут.
- Состояние — в Redis (тот же, что в compose, база 1): ETag и Last-Modified ленты, отметка «срок подошёл», пауза после блокировки, виденные URL с TTL 30 дней, очередь повтора страниц. TTL с запасом больше окна любой ленты: у sitemap Eurosport 48 часов, у остальных — дни.
- Очередь задач — своя, `arq:parsing`: воркер транскрипции берёт задачи из очереди arq по умолчанию в базе 0, и чужих задач никто не возьмёт.
- `run-once --source <key>` — один прогон без воркера: проверка источника (§4.3) и отладка.

### 4.7 Поведение на сайтах

Решается по источнику.

- **User-Agent** — `TennisWireBot/<версия> (+контакт)`: программа говорит, что она программа, и где найти её владельца. Открытые сайты такой бот пускают. Контакт — настройка, заполняется до деплоя.
- **robots.txt** — флаг `respect_robots` в профиле, решение при подключении (§4.3). Запрещённый путь, по которому сборщик всё же пошёл, пишется в лог. У стартовых источников нужное не запрещено.
- **Нагрузка.** Страницы одного сайта — по одной, не чаще раза в секунду. 429 с `Retry-After` — ждём, сколько сказали.
- **Блокировки** распознаются и записываются — как именно блокируют, от этого зависит решение:

| Признак | Что это |
|---|---|
| 403 | отказ |
| 429 | слишком часто; `Retry-After` — когда можно |
| 451 | запрет по закону или стране |
| 202 с пустым телом, страница Cloudflare или Akamai | JS-проверка, пускает только браузер |
| капча | |
| редирект на страницу согласия | cookie-баннер, бывает по стране |

  По умолчанию — растущая пауза от 1 минуты до часа и пометка в отчёте. Реакция под конкретный источник задаётся в профиле, когда блокировка увидена. Инструменты обхода — часть 5.
- **Откуда ходит сборщик** — страна и IP — влияет на блокировки: часть сайтов режет адреса по стране. Вопрос к деплою.

### 4.8 Безопасность

Ссылки в чужих лентах ведут туда, куда захотел автор ленты, в том числе во внутреннюю сеть (SSRF). Поэтому:

- только `http` и `https`;
- только хосты из `hosts` профиля, с проверкой после каждого редиректа, редиректов не больше пяти;
- таймауты и лимит размера ответа;
- JavaScript страниц не выполняется.

Образец проверки — `transcription-service/src/transcription/security.py`.

### 4.9 Результат

Локально, в каталоге из настроек (в `.gitignore`):

- `items-<дата>.jsonl` — по строке на новость. Формат — тот, что примет агрегатор (§5.1);
- `changes.jsonl` — изменения уже виденных статей (§4.4);
- `html/<key>/<хэш URL>.html.gz` — исходные страницы;

### 4.10 Тесты

pytest, respx, fakeredis. Логика — на самодельных лентах и страницах: каждый адаптер, канонический URL, фильтры, 304, виденные и их изменения, откат на лид, чужой хост и редирект на чужой хост, robots.txt, распознавание блокировок и пауза, отчёт при ошибке.

Настоящих страниц в тестах немного, и каждая держит что-то, чего самодельная не даст: одна страница без правил (Tennis Majors) — поведение trafilatura при обновлении версии; по странице на набор правил профиля (Eurosport DE, TNT Sports). Чужие тексты в репозиторий без нужды не кладутся.

### 4.11 Здоровье источников

Повтор (§4.4) чинит минутный сбой. Здесь — то, что больше: бан по IP, переверстка сайта, переехавшая лента.

После каждого прогона в Redis обновляется запись источника: первый и последний прогон, последний удачный, последняя новая новость, неудач подряд, с какого времени и как блокируют. Плюс окно из последних 50 окончательных исходов страниц: текст получен (сразу или повтором) или потерян (постоянная ошибка, повторы исчерпаны). Страница, которую ещё будут повторять, в окно не попадает: временные 404 Eurosport Italia (§4.4) тревоги не поднимут.

| Проблема | Когда | Что обычно значит |
|---|---|---|
| `blocked` | блокировка дольше часа подряд | бан по IP, новая защита от ботов |
| `failing` | 5 неудачных прогонов подряд без блокировки | лента отвечает ошибкой, сменился формат |
| `extraction` | потеряно 30% и больше из последних страниц, когда их хотя бы 20 | сайт переверстали, правила `extract` больше не подходят |
| `quiet` | нет новых новостей дольше `quiet_after` | переехала лента, опустел sitemap, сломался фильтр |

- Тик воркера раз в минуту проверяет все включённые источники и пишет в лог `source_unhealthy` (проблема, подробности), когда проблема появилась, и `source_recovered`, когда ушла. Не на каждом тике: лог не засоряется.
- `parsing health` — таблица по всем источникам с текущими проблемами; код выхода 1, если они есть: годится для cron или внешнего мониторинга.
- Пороги — настройки `health_*`. Межсезонье: новостей меньше, `quiet_after` по умолчанию поэтому сутки, а не часы.
- Куда уходят оповещения: сейчас только лог. Канал по [staff.md](staff.md) — Telegram, заводится к деплою вместе со стоком логов. В части 2 здоровье источников уходит в реестр агрегатора и во вкладку «Источники».
- Чего не видно изнутри: воркер не запущен или упал целиком. Это мониторинг процесса, к деплою.

## 5. Дальше

### 5.1 Хранение

- `aggregator-service` по образцу `user-service`: Spring Boot, PostgreSQL, Liquibase, Testcontainers. Порт 8095 — уже зарезервирован в `api-gateway`.
- Реестр источников — в агрегаторе, начальное наполнение — `sources.yaml`. Сборщик читает его через `/internal/**`. Списки аккаунтов в соцсетях (часть 6) редакция будет вести сама.
- Приём новостей пачкой через `/internal/**`, повторная отправка безопасна: upsert по `(источник, id)` и каноническому URL.
- У сборщика своя узкая роль. Не `service`: та открывает `/internal/**` `user-service` и `discussion-service`, включая стирание следа читателя. Аудитория у всех токенов realm одна, отличить сборщик можно только ролью. Имя роли и клиент — в auth.md.

Открыто: сколько хранить текст (предложение — 30 дней, метаданные дольше), что делать с исходным HTML.

### 5.2 Редакция

- «Источники» (`/desk/sources`): лента, фильтры по источнику, языку, поиск.
- «Новый материал по новости» — `/editor/new?from=<id>`: заголовок, `sourceUrl`, `sourceName`, язык, `aggregatorItemId`. Текст оригинала — панель рядом и контекст AI-чата, в тело черновика не копируется: чужой текст не уйдёт на сайт по ошибке.
- Перевода в сборщике нет: публикующий сам читает, переводит и адаптирует, DeepL есть в редакторе (`/api/translate/**`).
- Серверная проверка схемы `sourceUrl` в `content-service` ([staff.md](staff.md) §2) — вместе с этим: ссылки на чужие сайты пойдут потоком.

Открыто: «взято в работу» и связь новости с черновиком; поиск по китайскому — встроенный полнотекстовый поиск Postgres не делит такой текст на слова.

### 5.3 Сюжеты

Три вида «одинаковых»:

| Что | Пример | Как определить | Надёжность |
|---|---|---|---|
| Та же статья | одна статья в двух лентах сайта, ссылка с `?utm_…`, поправленный заголовок | канонический URL, id | точно — это одна запись (§3) |
| Тот же текст на разных сайтах | перепечатка агентства | сходство по шинглам слов (Жаккар) от ~0.8 | почти точно, в пределах языка |
| То же событие, разные тексты | финал Медведев — Рублёв у двух изданий, на RU и EN | многоязычные эмбеддинги, окно ~48 часов, игроки, турнир, раунд, счёт | с ошибками |

- Перепечатки и то же событие — отдельные записи, связанные в сюжет. Ничего не выбрасывается: у второго источника бывает цитата или деталь, которой нет у первого.
- Статья, которая содержит чужой текст и длинный свой, перепечаткой не становится: Жаккар симметричен (200 общих слов на 800 — 0.25). Вложенность считается отдельно и даёт пометку «содержит текст X».
- Ложная склейка хуже ложного разрыва: две карточки одного события — неудобство, одна карточка над двумя событиями — потерянная новость. Порог высокий, внутри сюжета видна каждая новость, склейку можно разъединить и объединить руками.
- «Вышел в финал» и «выиграл финал» близки по смыслу, но это разные события. Склеивать по одному смыслу нельзя — нужны структурные признаки: игроки, турнир, раунд, тип события, счёт.
- Сюжеты в интерфейсе — после замера на реальных данных: неделя сбора, ручная разметка ~200 пар, подбор порогов.
- Китайский и японский — без пробелов: шинглы по символам, а не по словам.

**LLM — открыто.** Возможные роли:

| Роль | Что делает | Оценка при 1000 новостей в день, Haiku 4.5 |
|---|---|---|
| Судья в серой зоне | на парах, где эмбеддинги не уверены: «одно событие или разные» | ~$15 в месяц |
| Разметка каждой новости | игроки, турнир, раунд, тип события, счёт в JSON — для склейки и для меток в ленте | ~$80 в месяц |

Оценка грубая, на 09.2026; русский текст дороже в токенах. Решение — после замера: сколько ошибаются эмбеддинги без LLM.

### 5.4 Закрытые сайты

ESPN, ATP, tennisworldusa, tennistemple закрыты антибот-защитой (Cloudflare, Akamai). Она смотрит на User-Agent, отпечаток TLS, выполнение JS, репутацию IP и частоту.

| Способ | Цена и риск |
|---|---|
| Притвориться браузером на уровне запросов (User-Agent, TLS-отпечаток) | дёшево; против серьёзных защит часто не помогает |
| Браузер без окна (Playwright) | сотни МБ на браузер, медленно, тоже распознаётся |
| Прокси, обычно домашние IP | платно за трафик |
| Платный скрапинг-сервис | платно за запрос, обход — не наша забота |

У всех — гонка с защитой, риск бана по IP, нарушение условий сайта. Новостей у таких сайтов в день немного, поэтому годятся и способы с оплатой за запрос. Решается в части 5, по сайту.

### 5.5 Соцсети

Instagram и Twitter: посты, сторис, ответы. Мир закрытых сайтов, плюс аккаунты, вход и лимиты на аккаунт. Сторис живут сутки: опрос частый, медиа сохраняются сразу. Ссылки на встроенные посты из статей (§4.4) — первый дешёвый вход.
